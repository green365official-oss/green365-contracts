Sepolia Ownership Status

Ownership has been renounced on the Sepolia test contract.

Owner address

0x0000000000000000000000000000000000000000

The contract owner now resolves to the zero address. Ownership renunciation is permanent. No account can use the inherited ownership-transfer functions after ownership has been renounced.

The Green365 token contract does not contain owner-gated minting, pausing, blacklisting, fee-setting, or balance-modification functions.

This ownership status applies only to the Sepolia test deployment. The Ethereum Mainnet contract has not yet been deployed.

The current plan is to renounce ownership on the Ethereum Mainnet deployment after final deployment checks and before public launch. This will be marked complete only after the transaction is publicly verifiable.

Renouncing ownership permanently removes administrative recovery through the ownership role. In this minimal token contract, the ownership role does not control token supply, transfers, balances, fees, pausing, or blacklisting.

Verified Contract Properties

  • Fixed supply created during deployment
  • No mint function available after deployment
  • No pause function
  • No blacklist function
  • No custom transfer tax
  • No hidden transfer fee
  • No owner function that changes token balances
  • Standard ERC-20 transfer behavior
  • Built using OpenZeppelin Contracts v5.6.0

Using OpenZeppelin's standard contracts reduces unnecessary custom-code risk, but it does not mean the Green365 deployment has received an independent professional security audit.

Independent paid audit

Not completed

The project is operating with a launch budget below $2,000. Current safeguards include minimal contract logic, OpenZeppelin components, testnet deployment, public source-code verification, and public transaction records. These measures are not a substitute for a professional audit.

Liquidity Plan

Mainnet liquidity and lock plan

  • G365 is planned to be paired with ETH on Uniswap.
  • The Liquidity Reserve contains 146,000,000 G365, representing 40% of the total supply.
  • The exact initial G365 contribution will be published at launch.
  • The exact paired ETH amount will be published at launch.
  • The final Uniswap pool version will be published at launch.
  • The fee tier will be published if applicable.
  • All relevant transaction links will be published.
  • The project plans to lock the resulting liquidity position for at least 6–12 months.
  • Lock-provider compatibility must be confirmed before launch.
  • The lock duration, unlock date, provider, and transaction proof will be published after completion.

Unlocked or founder-controlled liquidity can create a rug-pull risk because liquidity may be removed. A verifiable lock reduces this specific risk, but it does not remove token-price volatility, smart-contract risk, market risk, liquidity risk, or all project risk.
